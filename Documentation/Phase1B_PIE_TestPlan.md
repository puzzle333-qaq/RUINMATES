## Why it is unverified

- The agent has no interactive viewport: PIE input (TAB/ESC/mouse drag) cannot be driven, and
  two-client PIE requires an interactive editor session.
- Headless automation covers the underlying logic instead:
  `RuinMates.Inventory.*`, `RuinMates.Economy.*`, `RuinMates.UI.V4.*` (see delivery note for the
  exact run). Those tests do not prove input handling, cursor restore or replication behaviour.

## Known complex issues handed over

- `ARuinmatesLootContainer::GiveTo` decrements the shared `Contents` and refreshes
  `PublicContents` after `Backpack->TryAdd`; the two-player race is serialized by the server but has
  no explicit per-item reservation. Verify row 11 before claiming race-safety.
- The terminal uses `FInputModeUIOnly`; if a future screen needs camera control while open, this
  must be revisited (see `RuinmatesCharacter::OpenInventoryScreen`).
- Backpack contents are not persisted; only level/talents/loadout/funds survive travel.
